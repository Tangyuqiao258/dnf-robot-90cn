## 6. 阶段六：组队与发包跟随（自主取证 + 实现）

> 无需用户配合。资料：本机客户端/服务端、`DNF-90CN.git`（`GameGaurd` 静态补丁与插件加载、`Extensions/GameNative` 原生能力桥）、90CN 项目 Frida trace 模板、静态分析工具。

| 编号 | 任务 | 说明 |
|---|---|---|
| 6a | **自主抓包** | 扩展 `GameGaurd` 调试日志或新增临时调试插件，转储 party UDP 应用帧与副本内位置包；带开关与移除说明；必要时用 Frida/静态分析交叉验证 |
| 6b | **协议还原** | 从样本得到确定性结论：TQOS 应用层字段（位置/朝向/状态等）；写解析/构造 + 单测夹具 |
| 6c | **Robot 实现** | 解码队长状态驱动自身位置上报；房间切换沿用 `START_MAP`；异常回退 |
| 6d | **调试信息** | `CN90_FOLLOW_*` / `CN90_PARTY_UDP_*` 开关、上限、集中定义、便于整体移除 |
| 6e | **实机验收** | 实现完成并提供确定性证据后，由用户验证：真人+机器人副本内跟随、换房、进出、重连 |

> **阶段六结论（2026-09-28，已放弃）**：应用层位置帧已完成取证与实现（解码/构造、实机机器人间验证均通过），但本环境的客户端**不处理成员的 UDP 位置帧**（逐帧截图对比：队长移动时队员精灵不动），服务端也不向副本内队员投影位置（城镇区域名册排除 `CurrentRun != null` 的玩家）。经用户确认放弃副本内跟随：保留自动同意邀请与城镇跟随，移除 UDP 应用层实现、`START_MAP` 房间跟随以及全部 `CN90_PARTY_UDP_*` / `CN90_FOLLOW_TRACE_*` 调试开关。
