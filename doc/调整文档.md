# 调整文档

本文档记录本周期（审计修复 / 性能优化 / 交互治理 / 跟随规划）对配置、数据与运维方式有影响的调整。按阶段提交，提交信息见各条末尾的短哈希（以 `git log` 为准）。

## 配置迁移

| 项目 | 变化 | 处理方式 |
| --- | --- | --- |
| `[create] default_money` / `default_coin` | 原生后端遗留，已移除（无消费者） | 旧配置仍可启动：加载器显式识别这两个键并输出 `ROBOT_CONFIG_OBSOLETE`，不再报 unknown setting |
| `[create] reconcile_awakening` | 新增布尔项，默认 `true` | 启动对账时，已转职但未觉醒（`grow_type` 高 4 位为 0）的角色按 `grow_types` 中的正档位补齐觉醒；置 `false` 则保持原样 |
| 服务端设置界面标签 | `server_directory` 中文改为「服务端目录」、`server_host` 改为「游戏地址」 | 仅展示文案，键名与值不变 |
| `grow_types` 语义 | 觉醒档位（0/1/2），转职分支由 PVF 自动选择 | 转职仍不可配置；没有开放转职分支的职业保持未转职 |
| `[title]` / `[premium]` | 新段：称号开关与钉死的称号 id（`title_enabled` / `title_item` / `title_top_item` / `title_top_level` / `title_tier_items`）、黑钻开关与天数（`black_diamond_enabled` / `black_diamond_days`） | 配置解析是严格的，未知 section 会拒掉整份 `robot_config` 并以 1 秒周期重试——**这两个段必须在装上新二进制之后才写进线上 ini**。线上已写 `[title]`（`title_enabled=true`），`[premium]` 未写 |
| `jobs` | 已扩为 `0..15`（职业 11–15 全开） | 旧二进制遇到 11–15 号职业在无装扮桶时会栈溢出崩进程；先换 exe 再改 ini |
| `level_plan` | 新增 `区间:权重` 列表（如 `90-90:45,85-89:30,...`），机队等级按权重抽取 | 缺省时回落 `level_min`/`level_max` 区间；等级仍按「副本入场等级 + 1..4」的规则钳制 |
| `spawn_fixed` | 线上已改为 `false` | 让分发路径跑起来，把假人按城镇摊开 |
| `auto_emote` / `auto_trade` / `auto_chat_reply` / `auto_party_accept` / `auto_party_follow` / `auto_dungeon_revive` / `auto_dungeon_enter(_id/_difficulty/_interval_min_sec/_interval_max_sec)` | 新增能力开关（默认值见 ini；`auto_dungeon_enter` 默认**关**） | 与既有 `auto_*` 同族，改完 1 秒内热加载 |
| `robot_loadout` 标记 | 由「存在即已标记」改为版本号 `cn90LoadoutVersion`（当前 **7**） | 低于当前版本的下一次启动**整队重刷一次**，之后运营手改保留；以后改选装规则想推到存量，把版本号 +1 即可 |

## 数据修复（启动时自动执行）

- **战斗属性与经验**：写入等级时同事务写入 `character/ExpTable.tbl` 的累计经验阈值，并按 `.chr` 成长表重算 `character_subtype1_fields.stat_*`。存量机器人在启动对账时补齐。
- **成长对账**：未转职、未开放分支或损坏的 `grow_type` 会按 PVF 重新选择；已转职角色的觉醒档位在 `reconcile_awakening=true` 时补齐。对账失败不再中止启动。
- **任务门禁**：启动时清空并重写固定门禁集合（世界地图持久门禁标记完成，`[in progress]`、地城 `[quest connection]` 与 `[dungeon info]` 反向引用任务保持进行中）。
- **装备/装扮/宠物对账**：负载只有在校验窗口不满足时才重写（等级窗口、成套、职业、宠物/神器窗口）。修复后同一份数据库重复启动不再改写，已实测幂等。
- **启动清理**：仅处理名为 `前缀+UID` 且在 `robot_uid_start..robot_uid_end` 内的账号；账号不是完整可用角色时整账号删除（含全部角色）。删除前会在短事务内复核候选未变化。

## 运维观测关键字

| 关键字 | 含义 |
| --- | --- |
| `CN90_PVF_RESOLVED path=... source=...` | 实际读取的 PVF 与来源（env `PVF_ARCHIVE_PATH` / `Data/Pvf/Script.pvf` / 首个 `.pvf`） |
| `CN90_DATABASE_RESOLVED path=... source=...` | 实际使用的数据库与来源（适配器设置 / env `INVENTORY_DATABASE_PATH` / `Data/inventory.db`） |
| `CN90_DATABASE_SOURCE_CONFLICT` | 适配器设置与环境变量指向不同数据库，会以适配器设置为准 |
| `CN90_STARTUP_STAGE stage=... elapsed_ms=...` | 启动各阶段耗时（pvf_catalog、startup_inventory、对账、任务门禁、装备对账等） |
| `CN90_STAT_FALLBACK jobs=...` | 这些职业的 `.chr` 解析失败，属性使用零成长兜底表 |
| `STARTUP_INVENTORY_DELETE` / `..._DELETE_MORE` / `..._SKIP_CHANGED` | 启动删除明细（有界输出）与跳过原因 |
| `CN90_GROWTH_RECONCILED` / `CN90_QUEST_GATES_SEEDED` / `CN90_LOADOUT_RECONCILED` | 各对账阶段改写数量 |
| `[RobotMetrics] ... db_ms= db_ok= log_mb=` | 周期指标新增数据库探测延迟/状态与日志体积 |
| `CN90_PARTY_LEFT` / `CN90_PARTY_PREPARE_DEFERRED` | 队伍状态变化与入队准备重试（常开，行数有界） |
| `[STORE_NO_POINT] town=... has_point=...` | 摆摊轮次因**本城没有任何可占点位**而结束，不是传输或服务端失败。行数有界；计数进 `store_no_point`，**不进** `store_failed` |

## 行为变化

- 组队跟随保留城镇投影与自动同意邀请；副本内跟随经 2026-09-28 现场验证后放弃（客户端不处理成员 UDP 位置、服务端不投影副本内位置），相关实现与调试开关已移除。
- Web 全量文案中英双语；调度栏与商店状态不再固定英文；危险删除弹窗明确“只删除机器人账号（前缀+UID）、不可撤销”，并在执行后汇报删除账号/角色/登记数量。
- 清理（协议删除角色）与删除（按规则彻底清理，含离线）语义分离：正常缩容/下线使用下线，不使用清理。
- 装备/时装/称号/黑钻的发放从「能穿就行」变为按等级带 + 运营配置出成品规格：装备等级按 5 级取整、稀有度与强化/增幅按等级带、武器种类对口、护甲材质按转职分支对口、时装按等级分档（71 级以上成套稀有装扮）、称号按 id 钉死、黑钻按账号发。规则改动通过 `cn90LoadoutVersion` 推到存量。
- 在线人数由需求决定（`b5c91ce` 起）：浮动层跟随真人、需求集合过滤、超出需求的假人分批节流下线（一批 5 个、间隔 5s）；`auto_target_online_count` 现在是**需求上限**而不是填充目标。
- `[RobotMetrics]` 与启动日志增加数据库、日志体积与阶段耗时信息；日志轮转仍为 100MB × 5。

- 摆摊轮次的结束原因分成两支：找不到可占点位时走新增的 `ActionStateStoreNoPoint`，写一行 `[STORE_NO_POINT]`，计数进 `store_no_point` 而**不并入 `StoreFailed`** —— 否则空市场会触发 `store_failure_pressure`，把摆摊并发、概率与冷却一起压下去，等于让「没地方摆」去限流「去摆」的轮换（robot `496d2a9`）。
- 摆摊候选点位按地图的人群规则**预过滤**：容不下该摊位种类的图不再是候选，而不是先占点再被地图拒绝。实测 64 分钟窗口里 304/408 次摆摊失败来自这种「占完才被拒」，一次拒绝就结束整轮；判据按图 memoize，一轮每张图只查一次。末段那次拒绝仍在（它能挡住「占位与检查之间被别人拿走最后一个坑」）（robot `06ef641`）。
- 摆摊轮次结束后回到**需求钉位**，而不是跟随账号所在的城。`randomNormalPosition` 末尾那次无条件的 `ApplyConfiguredLocation` 已移除，该方法也从 `MaintenanceEnv` 上消失，避免后续适配器再把它接回来（robot `ac65242`）。
- `follow_account` **不再短路上线时的拥挤修复**：`PrepareOnline` 此前在 `FollowAccount` 非空时提前返回，连带跳过了把机器人搬出 Seria 门厅（38/1）的 `SpawnRepair`（该修复在故障期间触发 0 次）。服务端每次角色列表登录都会把角色放进那个共用门厅，而机器人自己的地图目录把 38/1 标成 `use=false`、无矩形、带 20 条通往各村的链接 —— 它是门厅，不是城镇（robot `1d226f4`）。
