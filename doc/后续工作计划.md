## 阶段 A：收尾与清理（零外部依赖，可独立完成）

### A1 属性投影：接线或删除（**决策点 → 2026-10-14 已定：A1-b 删除，已执行**）

**取证结论（2026-10-14，实机复现）**：服务端选角时**重算覆盖**，写入必被抹掉。
- 方式：对角色 26 离线写入特征值（`stat_strength=12345`、`stat_physical_attack=23456`、`stat_hp_max=34567`、`stat_level=777`、`stat_intelligence=11111`）→ 重新登录 → 读回 282 / 282 / 39400 / **777** / 265。PVF 可映射列全部被覆盖，仅 `stat_level`（不在重算集合内）保留。
- 服务端日志佐证：`dnf-character-stat-pvf-computed character_id=26 job=7 grow_type=19 level=56 ...`。
- 链路（`G:\90-CN\server-90\go-server`）：`game_select_resolve.go:45-56` → `characterPVFStatsNeedRepair` → `repairSelectedCharacterPVFStats` → `SaveCharacterFields(..., CharacterFieldStats)`；重算值 = PVF 成长表 + 固定兼容加成（HP+9800 / MP+10500）——后两项机器人侧算不出，接线必然对不上账，故排除 A1-a。

| 选项 | 做法 | 结论 |
|---|---|---|
| A1-a 接线 | 在 `loadout.go` 的写入事务里调 `BuildAdditionalInfo`，写入属性列；`ParseCombatStatFields` 用于对账校验 | **排除**：服务端每次选角重算覆盖，写了白写，还多一份必然不一致的数据 |
| A1-b 删除 | 移除 `pvf_character_stats.go` 中未被调用的部分及对应测试，能力矩阵中"战斗属性离线重算"维持"明确不实现"并写清服务端重算的依据 | **已执行（2026-10-14）**：删除 `BuildAdditionalInfo`/`CombatStatFields`/`ParseCombatStatFields`、HP/MP 兼容加成常量及两条对应测试；保留 `ProjectCharacterStatCatalog`/`ProjectLevelThresholds`/`LevelExpFor`（仍是 `cn90/growth.go` 的生产依赖）。依据已写进 `90CN能力状态.md` |

| 选项 | 做法 | 风险 |

## 阶段 C：新能力（每项都需先取证，取证不过就不做）

排序按"取证成本 / 预期收益"。

### C1 同区域私聊（成本最低，建议先做取证）

- 已知：90CN 只有同区域私聊（op17/op118），**没有区域/世界广播**；`CapabilityShout` / `CapabilityWorldShout` 因此关闭。
- 可能的真实需求：机器人对同区域真人说话做出回应，而不是单方面广播。
- 取证内容：服务端 op17/op118 的 handler 方向（是只处理客户端上报，还是会把消息投递给同区域其他客户端）；需要目标在线的前提是否满足。
- 通过则把 `CapabilityShout` 的语义从"广播喊话"降级定义为"同区域定向私聊"，而不是直接启用当前语义——**当前语义服务端做不到，不能靠开开关糊弄过去**。

### C2 拍卖 / 邮件（先静态分析服务端源码）

- 取证：在服务端源码里找拍卖与邮件的路由与 handler。找不到路由即与"公告"同类，直接长期关闭并写明原因。
- 本仓库已有 `dnf_mails` / `dnf_mailboxes` 等表在删除清单中，说明表结构存在，但**表存在不等于协议存在**。

### C3 组队 / 工会邀请（成本最高）

- 阶段六已放弃的是**副本内跟随**（客户端不处理成员 UDP 位置帧，服务端也不向副本内队员投影位置）。
- 但"自动同意邀请"与"城镇跟随"当初是保留过的（见 `优化与跟随规划.md` 阶段六结论），当前代码中**已无相关残留**（全仓 grep 无 `acceptInvite`/`partyAccept` 类实现）。要恢复需重新取证邀请链路。
- 开工前必须先确认：这条线当初取证到哪一步、结论是否仍成立，避免重复劳动。
