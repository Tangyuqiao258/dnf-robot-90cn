# 构建与发布

项目使用单进程 Robot，Web、调度器和适配器在同一生命周期内运行。

## 本地验证

```text
go test ./...
go vet ./...
go build ./cmd/robot
git diff --check
```

工具链要求：Go 1.26 及以上（`go.mod` 的 go 指令为 1.26.0）。发布与分发包必须使用 **Go 1.26.6 或更新** 构建，以包含 `govulncheck` 报告的标准库修复（html/template、crypto/tls、net/http、encoding/xml、encoding/asn1）。

`latest` Release 只保留最新提交的压缩包及其同名 `.sha256` 校验文件。新资产上传并更新标签后，发布作业会删除旧资产；上传失败时仍保留上一版供下载。

## 构建脚本

```text
deploy\build-robot.bat
```

脚本在仓库根目录执行，产物输出到 `deploy\output\`：

- `robot.exe`：Windows amd64（当前唯一允许运行的分发形态）。
- `robot-linux-amd64`：Linux amd64 交叉编译产物（见下方平台说明）。
- 构建参数与 CI 一致：`-trimpath -buildvcs=false -ldflags="-s -w -X main.version=..."`，并关闭 CGO。

## 随发行包发布

Windows 发行包由 Server-90 仓库的 `PACKAGE_LIGHTWEIGHT.bat` 统一组装：打包器从本仓库源码编译
`robot.exe`，并把 `deploy\soak\soak.ps1`、发行用的 `config.ini` / `robot_config.ini` 模板和
（若存在）PVF 目录缓存放进包内 `Robot\`。`deploy\build-robot.bat` 仍用于单独构建、压测和交叉编译。

## Windows

当前发布包只支持 Windows；`cmd/robot/main.go` 中的入口检查会有意拒绝在非 Windows 系统上启动，用于防止商业使用。生成物只放在 `deploy\output\`，不提交到仓库。配置、日志和运行时目录由程序首次初始化时按适配器能力生成。

构建前确认没有释放原生密钥、原生服务配置、市场/邮件配置或其他当前适配端不支持的文件。

## Linux

- 源码保持跨平台：`GOOS=linux GOARCH=amd64 go build/vet ./...` 必须通过，CI 的 `verify-linux` 作业会在 ubuntu-latest 上执行 vet 与全量测试。
- Linux 专属实现（RLIMIT 提升、`/proc` 资源采样、进程组管理、符号链接日志）随源码保留；移除入口检查后即可作为完整运行形态使用。
- 本仓库不发布 Linux 运行包，也不在 CI 中运行真实 90CN 服务端联调；Linux 实机运行记录需要部署方在目标环境按本文档流程补充。

## 适配端切换与运行期重置

当 `state/backend_selection.json` 的代次发生变化（或在旧安装上升级首次写入代次）时，下一次启动会重置 Robot 自有的运行期文件：

- 被移动的文件：`templates/`、`keys/`、`pvf/`、`state/`、`logs/`、`tmp/` 以及 `conf/robot_config.ini`。
- 它们会被移动到可执行文件同级的 `config.backend-bak.<UTC时间戳>/` 备份目录（父目录下保留最近 3 份），随后重新释放默认文件。
- `conf/config.ini`（含 Web 口令与端口）不会被重置。

因此：切换适配端后请重新编辑 `robot_config.ini`；旧内容可从备份目录取回。

从旧版本升级时，被移除的配置键（如 `default_money`/`default_coin`）会被识别并忽略，日志输出 `ROBOT_CONFIG_OBSOLETE`；新增键与行为变化见 [`调整文档`](调整文档.md)。


## 长稳压测（soak）

`deploy\soak\soak.ps1` 是长稳压测的唯一入口：档位、pid、守护日志和配置备份都落在 `<RobotDir>\soak\`，不留在 shell 历史或临时目录里，所以今晚起的压测明早仍找得到、停得掉。

```powershell
# 起 100 档压测（写档位、分离启动、挂上内存守护）
powershell -NoProfile -ExecutionPolicy RemoteSigned -File deploy\soak\soak.ps1 start 100

# 看状态
powershell -NoProfile -File deploy\soak\soak.ps1 status

# 停机器人和守护
powershell -NoProfile -File deploy\soak\soak.ps1 stop
```

默认值：`-RobotDir G:\90-CN\robot-run`，配置 `<RobotDir>\config\conf\robot_config.ini`，守护阈值 `-FreeFloorMB 3500` / `-WsCeilMB 4096`。

| 动作 | 做什么 |
| --- | --- |
| `start [tier]` | 备份 ini，写 `auto_target_online_count`，分离启动 `robot.exe`，挂上内存守护 |
| `status` | 档位、机器人 pid 与工作集、守护计数、守护日志尾部、最后一行 metrics、在线直方图 |
| `stop` | 杀掉守护进程与机器人，打印最后一行 metrics |
| `guard` | 内部用——`start` 分离出来的循环；不要手工调用 |

机器人和守护都是分离启动的，关掉发起压测的 shell 不会中断压测。若上一轮压测的机器人还活着，`start` 会拒绝启动——先 `stop`。

### 读日志

状态目录 `<RobotDir>\soak\`：

| 文件 | 内容 |
| --- | --- |
| `soak.pid` | 本轮启动的机器人 pid |
| `guard.log` | 每 10 分钟一行 `ok free=…MB soak_ws=…MB`，或一行 `TRIP` 及它执行的停止 |
| `robot-out.log` / `robot-err.log` | `robot.exe` 的 stdout / stderr |
| `robot_config.ini.bak-<stamp>` | `start` 改写档位前的配置 |

机器人自身日志在 `<RobotDir>\config\logs\robot.log`（跨轮次追加，不按轮次轮转，需按时间戳过滤）。

### `runtime running` 才是在线人数

`[RobotMetrics]` 一行里有三个字段看起来都像在线数，只有一个是真的：

```text
[14/10/26 05:01:20] [RobotMetrics] policy=store_expand target=100 actors=100
  leased=100 idle=0 state idle=0 assigned=0 online=0 running=69 busy=31
  releasing=0 runtime running=100 store=0 connecting=0 recycling=0 blocked=0
  cpu=2.3 mem_mb=1665 goroutines=415 online=100/0 online_window=11/0 ...
```

- `runtime running=<n>`：**这个才是在线人数。**
- `online=<n>`：`counts.StateOnline`，一个瞬时状态桶（这一行里 100 人在线它却是 0）。
- `online=<a>/<b>`：`stats.OnlineSuccess`/`stats.OnlineFailed`，自启动起的累计计数（100/0 = 累计登录成功 100 次）。

该行由 `internal/scheduler/auto_metrics.go` 构造；用任何字段之前先看那里。本项目已经不止一次因为望文生义拿错过数字。

`soak.ps1 status` 会对最近 4000 行 metrics 里的 `runtime running` 打直方图，就是为了这个。

### 参考跑：2026-10-14 的 20/100 档压测

这是清掉 B3 验收项的那一轮，实测数据：

- 20 档 00:16–05:00，100 档 05:01–09:34；100 档按守护观测跑了 **4h20m**（05:14:30 → 09:34:33），按 metrics 采样是 4h34m（05:01:09 → 09:34:59）。两者都过 1 小时验收线。
- 内存：27 次守护采样全 `ok`，阈值从未触发。`soak_ws` 在 1756MB 启动瞬时之后稳定在 1225–1251MB → 无泄漏。系统空闲内存从未低于 5287MB。
- 在线（`runtime running`，1554 个采样）：峰值 **100**（满档），首次 05:01:20、末次 09:20:12；稳定带 90–98，最低 86。
- 它是**掉电结束**的，不是计划停止，也不是预定的压测时长。将来引用这一轮时必须把这点说清楚。

## 安全部署前提

Robot 仅设计用于可信内网或单机环境：

- TCP 指令接口（`[Ports] RobotAPI`，默认 8111）监听 `0.0.0.0` 且不做鉴权，除危险删除外的命令对同网段可见。必须用防火墙限制来源，或仅在单机使用。
- Web 管理（`[Ports] Web`，默认 8112）默认口令为 `twadmin` 且无 TLS；首次部署后应立即修改口令，并避免把端口暴露到不可信网络。

### 口令存储

- 明文 `WebPassword` 仍然支持；在 Windows 上不会阻止其他本地用户读取 `config.ini`（仅设置了只读位）。
- 推荐改为哈希存储：用同目录的 `robot.exe -hash-password "<新口令>"` 生成一行 `WebPasswordHash`，写入 `[Web]` 段并删除 `WebPassword`。哈希算法为 PBKDF2-SHA256（210000 次迭代，随机盐）。
- 设置了 `WebPasswordHash` 后，敏感文件在 Windows 上会尽力收紧 ACL 到当前用户、SYSTEM 与 Administrators；FAT/exFAT 或网络共享不支持 ACL 时会静默跳过，此时请改用访问受控的安装目录。
